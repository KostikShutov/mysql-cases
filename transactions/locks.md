# Блокировки

## По области действия

### Строчная блокировка

Строчная блокировка — действуют только на одну строку таблицы базы данных, не ограничивая манипуляции над другими строками таблицы.

```sql
-- Блокировка на чтение
SELECT * FROM table_name WHERE id = 1 LOCK IN SHARE MODE;

-- Блокировка на чтение и запись
SELECT * FROM table_name WHERE id = 1 FOR UPDATE;
```

По русски: блокирует одну строку.

### Гранулярная блокировка

Гранулярная блокировка — действует на всю таблицу или всю страницу и все строки. Блокировка, ограничивающая манипуляции со страницей данных в таблице (набор строк, объединённый признаком совместного хранения) иногда называется страничной.

```sql
-- Блокировка таблицы на чтение
LOCK TABLES table_name READ;

-- Блокировка таблицы на чтение и запись
LOCK TABLES table_name WRITE;
```

По русски: блокирует таблицу.

### Предикатная блокировка

Предикатная блокировка действует на область, ограниченную предикатом. Обычно это блокировка по диапазону ключей. При такой блокировке для ключа или индекса указывается значение или диапазон значений, на которые распространяется блокировка. Такая блокировка (а также блокировка всей таблицы), помимо прочего, защищает от чтения фантомов и обеспечивает уровень изоляции транзакции Serializable.

```sql
SET TRANSACTION ISOLATION LEVEL SERIALIZABLE;

START TRANSACTION;

SELECT * FROM table_name WHERE condition;

-- Запросы на изменение чего-нибудь

COMMIT;
```

По русски: блокирует по диапазону ключей.

## По строгости

### Совместная блокировка (shared)

Совместная блокировка накладывается транзакцией на объект в случае, если выполняемая ей операция безопасна, то есть не изменяет никаких данных и не имеет побочных эффектов. При этом, все транзакции могут выполнять операцию того же типа над объектом, если на него наложена совместная блокировка, обычно такая блокировка используется для операций чтения.

```sql
SELECT * FROM table_name WHERE condition LOCK IN SHARE MODE;
```

По русски: блокирует запись, но не блокирует чтение.

### Исключительная блокировка (exclusive)

Исключительная блокировка накладывается транзакцией на объект в случае, если выполняемая ей операция изменяет данные. Только одна транзакция может выполнять подобную операцию над объектом, если на него наложена исключительная блокировка. Блокировка не может быть наложена на объект, если на него уже наложена совместная блокировка.

```sql
SELECT * FROM table_name WHERE condition FOR UPDATE;
```

По русски: блокирует и чтение, и запись.

## По логике реализации

### Пессимистическая блокировка

Пессимистическая блокировка накладывается перед предполагаемой модификацией данных на все строки, которые такая модификация предположительно затрагивает. Во время действия такой блокировки исключена модификация данных из сторонних сессий, данные из блокированных строк доступны согласно уровню изолированности транзакции. По завершении предполагаемой модификации гарантируется непротиворечивая запись результатов.

```sql
START TRANSACTION;

SELECT * FROM table_name WHERE id = 1 FOR UPDATE;

UPDATE table_name SET column = value WHERE id = 1;

COMMIT;
```

По русски: запрещает модификацию из других транзакций.

### Оптимистическая блокировка

Оптимистическая блокировка не ограничивает модификацию обрабатываемых данных сторонними сессиями, однако перед началом предполагаемой модификации запрашивает значение некоторого выделенного атрибута каждой из строк данных (обычно используется наименование VERSION и целочисленный тип с начальным значением 0). Перед записью модификаций в базу данных перепроверяется значение выделенного атрибута, и если оно изменилось, то транзакция откатывается или применяются различные схемы разрешения коллизий. Если значение выделенного атрибута не изменилось — производится фиксация модификаций с одновременным изменением значения выделенного атрибута (например, инкрементом) для сигнализации другим сессиям о том, что данные изменились.

```sql
CREATE TABLE table_name (
    id INT PRIMARY KEY,
    data VARCHAR(100),
    version INT DEFAULT 0
);

START TRANSACTION;

SELECT version FROM table_name WHERE id = 1;

UPDATE table_name SET data = 'new_data', version = version + 1 WHERE id = 1 AND version = 1;

COMMIT;
```

По русски: не ограничивает модификацию из других транзакцию, но отвалится на коммите, потому что использует особую колонку version.

К слову в доктрине есть:

```php
class LockMode
{
    public const OPTIMISTIC        = 1;
    public const PESSIMISTIC_READ  = 2;
    public const PESSIMISTIC_WRITE = 4;
```

OPTIMISTIC реализован через версию:

```php
#[Version, Column(type: 'integer')]
private int $version;
```

PESSIMISTIC_READ и PESSIMISTIC_WRITE – это shared и exlusive блокировки:

```sql
LOCK IN SHARE MODE
FOR UPDATE
```
